# Day 1 · Database: Setup & First Queries

## 1. Why this matters in interviews
Clients building full-stack apps ask the basics first: "SQL or NoSQL?", "what is an RDBMS?", "which data type would you use for money or a phone number?". Wrong data-type choices are the most common beginner mistake in real projects, and interviewers look for them.

## 2. Core concepts

### Database, DBMS, RDBMS
- **Database:** an organised collection of data that survives restarts.
- **DBMS** (database management system): the software that stores, queries and protects that data (concurrent access, crash safety, permissions).
- **RDBMS:** a DBMS that stores data in **tables** (rows and columns) with **relationships** between tables, queried with **SQL**. Examples: PostgreSQL, MySQL, SQL Server, Oracle, SQLite.

### SQL vs NoSQL (overview, deeper on Day 12)
| | SQL (relational) | NoSQL |
|---|---|---|
| Shape | Tables with a fixed schema | Documents, key-value, wide-column or graph |
| Relationships | Joins, foreign keys | Usually embedded or handled in application code |
| Consistency | Strong, ACID transactions | Often traded for scale/flexibility (varies by product) |
| Good for | Orders, payments, anything with relationships and rules | Flexible or huge data: caches, logs, catalogs, feeds |
Default for most business apps: **start with PostgreSQL** and add NoSQL where a clear need appears.

### Tables, rows, columns
```
customers (table)
 id | name         | city       <- columns (each has a name and a data type)
----+--------------+----------
  1 | Ananya Gupta | Delhi      <- a row (one record)
  2 | Rahul Desai  | Mumbai
```

### Installing PostgreSQL (macOS)
```bash
brew install postgresql@17
brew services start postgresql@17        # run it in the background
createdb interview_prep                  # make a database
psql -d interview_prep                   # open the SQL shell
```
If `psql` is not found after installing, add it to your PATH: `echo 'export PATH="/opt/homebrew/opt/postgresql@17/bin:$PATH"' >> ~/.zshrc` and open a new terminal.

Handy `psql` commands: `\l` list databases · `\dt` list tables · `\d table` describe a table · `\i file.sql` run a file · `\q` quit.

### Data types you need
| Type | Use for | Example |
|---|---|---|
| `INT` / `BIGINT` | whole numbers, ids | `42` |
| `NUMERIC(10,2)` | **money**, exact decimals | `499.50` |
| `VARCHAR(n)` | text with a sensible limit | `'Delhi'` |
| `TEXT` | text of any length | review comments |
| `BOOLEAN` | true/false | `is_active` |
| `DATE` | a calendar day | `'2026-11-16'` |
| `TIMESTAMP` | date + time | `'2026-11-16 10:30'` |
Floating types (`REAL`, `DOUBLE PRECISION`) are approximate. Never use them for money.

### CREATE TABLE
```sql
CREATE TABLE notes (
    id          INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  -- auto-numbered
    title       VARCHAR(100) NOT NULL,
    body        TEXT,
    is_pinned   BOOLEAN DEFAULT FALSE,
    created_at  TIMESTAMP DEFAULT now()
);
```

### INSERT
```sql
INSERT INTO notes (title, body) VALUES ('Groceries', 'milk, eggs');            -- one row
INSERT INTO notes (title) VALUES ('Idea 1'), ('Idea 2'), ('Idea 3');           -- many rows
```
Always list the column names. Columns you leave out get their default (or NULL).

### SELECT basics
```sql
SELECT * FROM customers;                        -- every column (fine for exploring)
SELECT name, city FROM customers;               -- only the columns you need
SELECT name, price * 1.18 FROM products;        -- expressions
SELECT 1 + 1;                                   -- no table needed
```
`SELECT` only reads. It never changes data.

## 3. Common pitfalls / gotchas
- **Quotes:** strings use **single** quotes `'Delhi'`. Double quotes `"name"` are for identifiers.
- **Phone numbers, pincodes, ids you never add up are text**, not `INT`: leading zeros, `+91` and spaces would be lost.
- **Money in `FLOAT`:** rounding errors. Use `NUMERIC(p,s)`.
- **`SELECT *` in application code:** fragile (columns change) and slow (fetches columns you do not need). Name the columns.
- **`NULL` is "unknown", not 0 or `''`.** `NULL = NULL` is not true (details on Day 2).
- **`INSERT` without column names** breaks the day someone adds a column.
- **Keywords are case-insensitive, identifiers are folded to lower case** unless quoted. Pick `snake_case` and stay consistent.
- **Forgetting the `;`** in `psql` just waits for more input. Type it and press Enter.

## 4. Top interview questions

1. **What is an RDBMS?**
   A database system that stores data in related tables and uses SQL to query it. Relationships are expressed with keys, and it provides ACID transactions so data stays correct even with concurrent users and crashes.

2. **DBMS vs RDBMS?**
   A DBMS is any system that manages data (files, hierarchical, document stores). An RDBMS is the relational kind: tables, a fixed schema, keys and joins. Every RDBMS is a DBMS; not the other way round.

3. **SQL vs NoSQL: how do you choose?**
   If the data is structured, has relationships, and needs transactions (orders, payments, users), choose SQL. If the shape varies a lot, volume or write rate is huge, or access is simple key lookups (caches, logs, feeds), consider NoSQL. Many systems use both.

4. **Why PostgreSQL?**
   Open source, fully ACID, rich types (JSON, arrays, UUID), strong SQL support (CTEs, window functions), good indexing, extensions like PostGIS. It handles both relational and some document workloads.

5. **Which data type do you use for money, and why?**
   `NUMERIC(p, s)` (or integer paise/cents). Floats cannot represent most decimals exactly, so sums drift.

6. **Which type for a phone number?**
   `VARCHAR`/`TEXT`. It is an identifier, not a quantity: you never add phone numbers, and you must keep `+`, leading zeros and spaces.

7. **`VARCHAR(n)` vs `TEXT` in PostgreSQL?**
   Same storage and performance in PostgreSQL. Use `VARCHAR(n)` when there is a real business limit (like 10 digits), otherwise `TEXT`.

8. **`DATE` vs `TIMESTAMP`?**
   `DATE` stores only the day (birthdays, hire dates). `TIMESTAMP` stores date and time (when an order was placed). For apps across time zones, prefer `TIMESTAMPTZ`.

9. **What does `SELECT *` do and why avoid it in production code?**
   It returns every column. It wastes bandwidth, can leak columns you did not mean to expose, and breaks code when the table changes. List the columns you need.

10. **What is a primary key?**
    A column (or set) that uniquely identifies each row and is never NULL. It is how other tables refer to the row. (Details on Day 4.)

## 5. One-line cheat sheet
**RDBMS** = tables + relationships + SQL + ACID; start with **PostgreSQL**; money → `NUMERIC`, phone → `TEXT`, flags → `BOOLEAN`, moments → `TIMESTAMP`; `CREATE TABLE`, `INSERT INTO t (cols) VALUES (...)`, `SELECT cols FROM t`; strings in **single quotes**; name your columns, avoid `SELECT *`.
